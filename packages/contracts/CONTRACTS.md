# Contract interface freeze

This package contains implementation-free interfaces, shared libraries and unit tests. `app/SPECS.md`, Chain design (Arc, Uniswap v4), and the final decisions below govern implementation. Money is micro USDC; token quantities are 18-decimal room nights. The four implementation tracks must preserve this ABI and the frozen event fields in `INightTypes.sol`.

## Decisions

1. **IDs.** `NightKeyLib.night(propertyId, roomTypeId, date)` hashes the UTF-8 bytes of `propertyId:roomTypeId:date`, where date is `YYYY-MM-DD`. `NightKeyLib.property(propertyId)` hashes the UTF-8 property ID. These string helpers are for scripts/tests; contracts accept and store bytes32 IDs. `NightConfig.night` carries the canonical night ID, `property` the property hash, and `roomType` the room-type hash. `checkIn` is the separate Unix timestamp for 15:00 UTC on that date, not an input to the night hash. There is no UTC-day placeholder or on-chain derivation from prehashed components.
2. **Maker custody.** `NightToken.routerTransfer(from,to,amount)` bypasses allowance only for the two routers fixed at construction/factory initialization. It preserves cap and holder-list updates. Routers may call it only inside an atomic Order fill after on-chain signature, nonce, expiry, size, remaining fill and balance verification. Ordinary ERC-20 approvals remain available for owner-authorized transfers and direct pool sells; there is no Permit2 NightToken pull. Permit2 uses **AllowanceTransfer solely for taker USDC**: prior USDC approval to Permit2 and router-specific Permit2 allowance, with no embedded permit payload.
3. **Orders.** Both routers use `{name: "NightShares", version: "1", chainId, verifyingContract: TradeRouter}`. The exact type string is `Order(bytes32 night,uint256 size,uint256 price,uint64 expiry,uint256 nonce,address maker)`. TradeRouter owns all maker nonces and filled amounts keyed by domain-qualified order digest; `cancelAll()` increments the maker nonce for both routes. BookingRouter has no independent domain, cancellation or fill storage. Its active booking/void path calls restricted `TradeRouter.fillBookingAsk(ask,taker)`, which verifies `taker == BookingRouter.msgSender()`, verifies and accounts for the fill, pulls tokens into BookingRouter, pays the maker, distributes fees/rebate and emits Trade in the same transaction. BookingRouter prefunds gross plus fee; failure rolls back the whole booking. Direct buys reuse the same internal verification. Order size and each partial fill must be positive multiples of 1e17; filled plus requested quantity cannot exceed size. Price is micro USDC per 1e18. `OrderLib.fillCost` is `ceil(qty*price/1e18)`; taker pays gross plus separate fees, maker receives that gross. Fees round half up. Partial order fills are allowed; requested route quantities must fill completely or revert. Default expiry is 24 hours off chain, not an on-chain maximum.
4. **Cutoff.** Timestamp freezes ordinary trading even before settlement. One permissionless `Settlement.settleCutoff(night)` snapshots all holder balances, collects them, redeems their aggregate into the pool, applies one half-up 30% haircut to the recovered held reserve and sends it to RebatePool. The remaining reserve is allocated pro rata with floors to the snapshots. No holder USDC transfers occur during settlement. Holders later call `claim(night)` for their own entitlement, consumed before transfer; `claimable(night,holder)` reports unpaid amounts. Emit `CutoffReleased(bytes32 indexed night,uint256 roomsReturned,uint256 refundPerNight)` and `CutoffClaimed(bytes32 indexed night,address indexed holder,uint256 amount)`. `roomsReturned` is an 18-decimal quantity; `refundPerNight` is the floored refund for 1e18. Residual USDC after the last claim goes to RebatePool. Zero-held settlement must not divide by zero.
5. **Opening.** `MAX_S = 100e18` (100 rooms); S must be positive whole rooms. `NightFactory.openNight` validates configuration, derives X, deploys/initializes the token, mints exactly S to NightVault, initializes the pool and calls `NightVault.openNight`. It does not enable trading. The bound host calls factory `addLadderChunk(night,fromRoom,toRoom)` until complete; factory delegates to the vault. Ranges are zero-based half-open, contiguous, nonempty, begin at `nextRoom`, and end no later than S/1e18. Each room-index salt is added once, with one unlock per chunk. Factory and vault completion views must agree. Hook and both routers reject trading until all positions exist. Chunks after cutoff are rejected; cutoff must also safely close an incomplete opening. Implementers measure opening and worst-case cutoff gas at S=100.
6. **Property binding.** **NightFactory** exposes `bindProperty(bytes32 property,address hostPayout,uint64 deadline,bytes sig)`. Anyone may relay the current Settlement attester's signature under the factory's NightShares/version 1 EIP-712 domain, type `BindProperty(bytes32 property,address hostPayout,uint64 deadline)`. Reject expired signatures, zero payout, consumed digests and already-bound properties. No first-opener registration and no rebinding. Only the bound payout address may open; `config.host == msg.sender == ownerOf(property)`. Hosts need Orb and fewer than two incidents on that payout identity. Attester onboarding must keep the same payout identity across that host's properties.
7. **Identity.** `humanId` is uint256, the World ID uniqueness nullifier for fixed enrollment action `night-shares-enroll`, never a login/session ID. `linkWallet(uint256 humanId,address wallet,uint64 deadline,bytes sig)` uses attester-signed `LinkWallet(uint256 humanId,address wallet,uint64 deadline)` under the registry domain. A wallet links to at most one nonzero human. Only distinct attester-signed `relinkWallet` may change that mapping, with type `RelinkWallet(uint256 humanId,address wallet,uint64 deadline)`. Consume signature digests and enforce deadlines, including relinks back to old IDs. Attester records Device/Orb verification through `setOrb`; platform may rotate attester or ban false reporters. Caps sum per humanId across wallets, including agent wallets. Relinks must preserve live aggregates and bans; the safe implementation choices are described under Open.
8. **Supply and dust.** Mint exactly S, never an extra dust buffer. Each room uses the tick-rounded boundaries and standard floored amount0 liquidity formula in LadderMath, including the intermediate Q96 floor. Deposit `getAmount0Delta(lower,upper,L,true)` for each position; reject a curve if any amount exceeds 1e18, has zero liquidity/collapsed ticks, or differs from 1e18 by more than 1e9 wei. The sum is <= S, as tested for 15 and 100 rooms. Unplaced `S - sum(deposits)` remains in NightVault outside the pool, cap, holder list and holder refund reserve. Settlement calls `burnVaultDust` at cutoff; this does not increase earned booking/void burns. Nonexcluded balances and transfers remain whole tenths; internal vault/manager/Settlement accounting may carry wei. Never clear or donate token credit as a hidden loss. **Full S sellout through pool-only exact-output swaps remains mathematically incompatible with nonzero excluded dust; see Open.** Tests establish inventory conservation and tolerance, not a full-sellout guarantee.
9. **Walks.** `WalkAttestation` fields remain `{bytes32 reportId,bytes32 bookingId,bytes32 property,address guest,uint256 paid,bytes32 evidenceHash,uint64 reportedAt,uint64 deadline}`; verifying contract is Settlement. Validate signature, booking guest/property/paid, replay guards, reporting within 24 hours of recorded 15:00 UTC check-in, deadline, registry verification and reporting ban. Attester certifies reception presence and no desk check-in. Refund exactly 1x complete recorded paid, including fees, from property pending payouts first and CoverFund second. Only the fund advance becomes host debt, repaid from future payouts. **If pending plus fund cannot cover the refund, revert the entire report** for retry; do not record unpaid guest debt, consume replay guards or increment incidents. Two accepted incidents on the bound host payout identity suspend new openings. Debt and incidents share that payout identity across bound properties; wallet relinking does not change historical payout keys.
10. **Events.** Preserve the complete field lists and indexing in INightTypes: Trade, Booked, Recalled, Swept, CutoffReleased, CutoffClaimed, WalkPaid, OrderCancelledAll. Pool Trade is emitted by NightHook; ask Trade by TradeRouter, including delegated booking fills; Booked by BookingRouter; Recalled by NightToken; Swept by NightVault; cutoff and walk events by Settlement; OrderCancelledAll by TradeRouter. Recall does not emit a duplicate Trade. Trade notional is gross and fee is separate.
11. **Deployment.** PoolManager, USDC and Permit2 addresses are constructor/deploy configuration, never hard-coded constants in src/. All routing and excluded endpoints are fixed at construction or one-time factory initialization. No arbitrary router allowlist, liquidity provider, donation route, parameter mutation or host withdrawal is added.

## Contract responsibilities and calls

| Contract | State and access contract |
| --- | --- |
| NightFactory | Immutable dependencies, attested property owners, configs, token addresses and canonical pool keys. Supports deterministic token prediction and chunk coordination. |
| NightToken | ERC-20 balances, immutable endpoints/night/S/X, aggregate human balances, burned count, descending holder links. Fixed excluded endpoints: vault, manager, routers, Settlement, zero. Public getters and operations are in INightToken. |
| NightVault | Sole owner of positions and room-index salts; opening progress, unplaced dust, removed ranges, cutoff flag, pending USDC per property. No administrator. Anyone may sweep fully earned positions below P(b). Pay pending to a walked guest only through Settlement; net debt before sending remaining payout to the bound host. |
| NightHook | Immutable endpoints and fee recipients; owner can pause trading only. Validate PoolManager caller and original callback sender. Never trust tx.origin or unverified hook data. |
| TradeRouter | Shared order verification, nonce/fill state, active user and reentrancy guard. Orb trading, exact-output buys and exact-input token sells, live cheapest-first interleaving of supplied asks and pool, maxPaid/minReceived including fees. |
| BookingRouter | Active user, guard and immutable booking records. Device/Orb guests buy and burn 1e18 via pool/asks <= X, then recall largest holders. Host human can buyAndVoid without recall. Uses shared TradeRouter verification and prefunds its fills. |
| Settlement | Attester rotation by platform; walk replay/evidence, payout-identity debt/incidents, atomic cutoff snapshots and pull claims. Active cutoff is the only post-cutoff swap exception. |
| CoverFund | Immutable USDC/Settlement, exact payments only by Settlement, permissionless deposits, no withdrawal administrator. Insufficient funds revert. |
| RebatePool | Shared USDC balance; maker rebates only in router fills, checking the live pool reference price itself. Anyone may deposit; no withdrawal administrator. |
| HumanRegistry | Attester-signed enrollment wallet links, verification levels, replay protection and permanent walk-report bans. uint256 human IDs across every public identity ABI. |

NightToken recall pops the largest holder, prefunded by BookingRouter at X; the holder receives X less the base 1.3% fee. Ties sort by ascending address. Validate transaction-scoped insertion hints; fallback traversal is bounded to 64 nodes, otherwise revert. Every nonexcluded recipient is verified. Cap is max(1e18,30% of S), summed per humanId.

Hook permissions enable only beforeInitialize, beforeAddLiquidity, beforeRemoveLiquidity, beforeSwap, afterSwap, beforeDonate and both swap return deltas. Disabled callbacks revert UnsupportedCallback. Initialization checks factory sender, registered currency0 token < configured USDC, fee 0, spacing 1 and initial lower tick. Add-liquidity callbacks accept only expected vault-owned chunk positions. Removal accepts only vault-owned earned positions or Settlement-authorized cutoff with vault.closing. Swaps require complete ladder, authenticated immutable router/active user, pre-cutoff timestamp and unpaused state. Settlement's active cutoff redemption pays no ordinary swap fee. Donation always reverts.

Do not nest PoolManager unlocks. Settlement finishes its redemption unlock before calling NightVault for position removal in a separate unlock. Every callback validates PoolManager and an active operation initiated by its own entry point. Clear execution state after settlement; reject reentrancy and reconcile all deltas. Booking records are committed only after atomic payment, custody and burn succeed.

Buys use `zeroForOne=false`, positive `amountSpecified`, exact output NightToken. Sells use `zeroForOne=true`, negative `amountSpecified`, exact input NightToken. Users transfer/approve sold NightToken through ordinary ERC-20 custody, not maker routerTransfer. Verify actual deltas equal requested quantities; price-limit partial route fills revert. USDC is unspecified in these ordinary swaps, so afterSwap takes its fee. beforeSwap's USDC-specified branch remains available in the callback contract.

## Numerical rules

F and X are micro USDC per room; k is WAD; S is rooms times 1e18. `priceWad` returns micro USDC per room times 1e18, so raw currency1/currency0 is priceWad/1e36. Integer square root floors to Q64.96; each boundary uses floor(log_1.0001(rawPrice)), including negative ticks. Adjacent rooms reuse exactly the same boundary. Reject zero F/k, fractional or excessive S, unsupported prices, collapsed ticks and zero liquidity. Flat curves are unsupported. Derive X as the exponential endpoint times 1.25, half up once to micro USDC; check and store it at opening.

FeeMath returns WAD rates, including second-level late interpolation: lateFee(36 hours)=0.1565. Total fees round half up. Base shares are host/platform/cover = 100/20/10 bps, with platform receiving the micro remainder after bounded half-up host and cover shares. RebatePool receives late excess and the host share on host self-trades. Compare human IDs for host-self fee treatment, including alternate wallets. Pool buys pay gross plus fees; pool sells receive gross less late fees. Ask buyers pay gross plus base fees and makers receive gross. Recall retains its separate seller-fee rule. Maker rebates are separately funded, at most the available RebatePool balance, and require ask price <= 1.05 times the current pool price.

Cutoff uses actual recovered held reserve, not the continuous model or off-chain guide price. For F=6000 USDC, k=1.2, S=15, the unquantized ladder gives room seven 10092.165898 USDC, sellout 173962.375527 and q=6/h=4 reserve 33183.415221. SPECS figures 33192/5809/9958 are rounded continuous illustrations. Tests compare the tick ladder with the market-model ladder below 0.03% relative error and use separate illustration tolerances.

## Open

- **Blocking full-S sellout:** if D positive token wei remain in the vault and must be excluded from the pool until burned, pool inventory is at most S-D. Exact-output swaps cannot deliver S. Even zero unplaced dust may leave rounded-down swap output below deposited amounts. A final-tenth path combining pool output and vault inventory would change the stipulated dust rule; accepting floor(pool-output/1e17) sellable tenths would change the full-S rule. No extra mint, hidden credit clear or full-sellout claim is made here. Coordinator selection is required before the end-to-end sellout test can be specified.
- **Relink bookkeeping:** choose atomic migration across all live nights with destination cap checks, or prohibit relinks while the wallet has any live holdings. Either requires an enforceable registry/token bookkeeping mechanism; never merely change humanIdOf and leave cached aggregates stale. Replay digests must remain consumed after later relinks. Ban continuity and verification provenance must be enforced.
- **Catalog commitment:** hashed night IDs cannot be reconstructed from hashed component IDs. Decide how opening proves canonical night/property/date association and authenticates checkIn without changing the required string hash (for example an attested config). Until then the bound host supplies these fields; off-chain clients must validate catalog consistency. Catalog IDs containing ':' need an unambiguous upstream restriction.
- **Gas and integration:** measure chunk sizes and worst-case 1000-holder cutoff gas; if cutoff exceeds the chain budget, the required single-transaction cutoff needs a further decision. Full sellout, router authorization, relink preservation, walk rollback and chunk interleaving require implementation-level tests; current package intentionally contains no application implementations.
- **Moderation:** on-chain settled walk incidents are final. False-report reversal is not part of Settlement's ABI; the API moderation stub requires a later explicit decision if reversal is desired.

## Parallel implementation boundaries

1. NightFactory and NightToken: binding, opening/chunks, caps, holder list and router-gated custody.
2. NightHook and NightVault: ladder validation, position ownership, fees, sweeps and cutoff removal.
3. TradeRouter and BookingRouter: shared order state, atomic booking ask entry, Permit2 USDC and swap routing.
4. Settlement, CoverFund, RebatePool and HumanRegistry: claims, walks, attestation verification and identity bookkeeping.

Resolve the listed cross-contract open points before promising full-S integration. Interfaces remain implementation-free; test doubles must not be presented as production contracts.
